# プロジェクト憲章 (Constitution) — ろんりあそび

本憲章はすべての仕様・計画・実装に優先する、変更しない原則である。
変更する場合は理由と日付を末尾の「改訂履歴」に記録すること。

## 第1条 子どもの安全を最優先する
- 個人情報（名前・年齢・位置情報・音声・写真など）を一切収集しない。
- 広告、外部リンク、課金要素、チャット機能を置かない。
- アクセス解析・トラッキングスクリプトを読み込まない。
- 進捗データは端末内（localStorage）のみに保存し、サーバーへ送信しない。

## 第2条 文字に頼らない
- 対象は 4〜5 歳。文字が読めない前提で設計する。
- 指示はアイコン・音声読み上げ・アニメーションで伝える。
- 表示する文字はひらがな（必要に応じてカタカナ）のみ。漢字を使わない。

## 第3条 失敗しても叱らない
- 不正解は「もういちど やってみよう」のやさしいフィードバックとし、減点表示や赤い×を出さない。
- 正解は必ず褒める（アニメーション＋音声）。
- 不正解でも何度でも挑戦でき、先に進めなくなる状況を作らない。

## 第4条 小さな手でも操作できる
- タップ領域は最小 64×64 px。
- タブレット（横・縦）を優先し、スマートフォンでも横スクロールなしで遊べること。
- ダブルタップ・長押し・精密なドラッグを必須操作にしない（タップだけで完結する）。

## 第5条 短く、達成感のある体験
- 1 ゲーム = 5 問。1 セッションは数分で終わる。
- 終了時に必ず「ごほうび画面」を出す。

## 第6条 仕様駆動で開発する
- 仕様（spec.md）→ 計画（plan.md）→ タスク（tasks.md）→ 実装 の順を守る。
- 仕様の受け入れ基準は自動テストで検証できる形で書き、テストで担保する。
- 仕様にない機能を実装しない。必要になったら先に仕様を更新する。

## 第7条 シンプルな技術
- サーバーは Python（Flask）、Vercel のサーバーレスで動作すること。
- フロントエンドはビルド工程なし（HTML / CSS / 素の JavaScript）。
- 画像は絵文字と CSS で表現し、権利処理の必要な素材を使わない。
